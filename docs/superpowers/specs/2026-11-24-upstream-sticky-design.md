# 最新上游兼容同步与粘滞渠道故障切换

用户要求同步最新上游并保留定制功能；会话粘住的渠道连续失败两次后解除绑定、冻结并切换到下一个可用渠道。上游来源固定为 `v3.5.1` / `33f5e797836ac91d958022e9f4ca53c30d0432ec`，定制基线为 `9197ba2c704e7731d602411e8ae86d188057fee7`。

## 方案与实现判断

采用兼容回移：上游已移除代理订阅并更换插件和手机端架构，直接合入会破坏本仓库必须保留的功能。逐项记录采纳、已实现及暂缓项，保持定制 Docker、路由组、上游模型选择、Key 权限、倍率和代理订阅。

渠道故障使用独立的进程内状态，复用现有熔断时长配置，默认 60 秒。现有失败退避仅改变排序，不能承担“冻结期间禁止使用”的要求；现有熔断阈值和开关属于其它功能，不能通过改它们代替本需求。以下计数和作用域由实现者依据现有代码作出，用户需求的固定阈值为两次。

## 可观察行为

- 对开启粘滞的路由组，按“路由入口 + 渠道成员”累计连续失败；成员内的账号/Key 不应让故障渠道立即绕过冻结。第一次可恢复的失败重试当前绑定，第二次失败解除该渠道的匹配绑定并冻结。新选中的渠道也使用两次失败阈值。
- 冻结时间使用 `routingBreakerTimeoutSeconds`，范围沿用现有 10～600 秒，默认 60 秒；到期恢复参与。该冻结独立于普通熔断开关。
- 成功完成响应后清零失败数；仅收到 HTTP 200 响应头或第一段内容不算完整成功。冻结期间迟到的在途成功不得恢复旧绑定或提前解冻。
- 首内容之前可以重试和切换；已经向客户端发出内容时保持同一条响应，断流只影响后续选路，不启动第二份回复。
- 手动取消、客户端丢弃响应流、权限或请求参数拒绝不算渠道故障。限额与凭据失效仍遵守既有冷却、刷新和禁止重发规则。
- 冻结在同一路由入口的其它会话中也生效；其它入口和不相关成员不受影响。嵌套路由解除匹配的层级绑定。严格粘滞仍保留第一次失败时的绑定，达到两次后同样允许切换。
- 所有成员不可用时返回可读错误和可知的等待时间；不得绕过冻结、Key 范围、账号启用状态或代理配置回退直连。
- 故障计数和冻结有界，不落盘、不改变数据库 schema。管理清除会话、路由配置变更与在途世代保护保持兼容。

## 上游适配范围

本批独立评估数据库锁防重入（`00bfca65`）、入口页与 Service Worker 缓存修复（`a4ea2c11`）、请求筛选缓存（`26c38327` / `e4d8e3f7`）以及失败解绑（`b9c8fa05`）。失败解绑适配为用户指定的两次阈值。只有经过失败回归及兼容验证的补丁纳入候选；新版 WASM、统一容量、计价、登录、移动架构和删除订阅的变更不通过覆盖文件引入。

## 验收与发布

先验证旧代码失败，再验证候选成功。覆盖连续失败、成功清零、冻结到期、并发迟到、嵌套层级、流后失败、取消、受限 Key、全部冻结、静态缓存、锁重入和请求筛选刷新；运行完整 Rust 测试、桌面/手机构建及现有路由、协议、凭据和真实代理订阅回归。

代码和验证完成后准备版本与逐条发布日志，按 release-flow 取得本批确认再提交和推送 beta。确认前保持版本号 `3.4.3-beta.1`，不部署生产候选。GitHub 和服务器的发布授权不沿用已经完成的上一批日志。
