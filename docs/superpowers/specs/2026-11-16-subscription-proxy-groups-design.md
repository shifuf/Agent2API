# 订阅代理组选择与测速

状态：用户已确认（“可以继续”）。范围：接续内核代理链修复，补齐截图所示 Clash Verge 式使用流程。

## 目标与现状

用户需要先选择前置节点，再从落地组选择 IP，并能够测速。界面要像截图一样按原订阅代理组展示当前选择，而不是把几百个节点平铺后让用户猜依赖。

当前桌面代理页面只有代理池表格，订阅管理位于弹窗；手机端也只有节点列表。内核已能保留 `dialer-proxy` 依赖的组，但只导入被依赖的组，所以作为最终出口的“落地-US-ISP”组还没有操作入口。当前选择未持久保存，专用监听器指向固定节点。现有测试是连通性与出口 IP 检查，不是下载速度测试。

## 方案

采用“代理组卡片 + 节点列表”，作为网络代理页面的订阅使用视图；保留代理池管理入口。复用现有 React 组件、管理 API 与本地 Mihomo 控制器。

- 仅给现有表格增加前置下拉框：改动少，但会丢失原订阅组结构，多组和嵌套组不好理解，不采用。
- 按原订阅显示可折叠代理组卡片：能直接对应用户截图，也能表达前置和落地选择，采用。
- 嵌入完整 Clash 管理面板：引入另一套认证、界面与数据管理，和现有账号代理引用脱节，不采用。

## 展示与交互

每个订阅内按原组顺序展示卡片。组名和类型来自订阅，不硬编码“前置”“落地”名称。根据 `dialer-proxy` 展示实际依赖链。

```text
前置-机场                         [延迟测试] [展开]
Selector · 当前：日本 025 · 85 个节点

落地-US-ISP                       [延迟测试] [展开]
Selector · 当前：US-静态01 · 203 个节点
前置：日本 025 → 落地：US-静态01

展开： [搜索名称 / 地址] [原顺序 / 延迟排序]
● US-静态01   节点地址   128 ms   [测速] [检查出口]
○ US-静态02   节点地址   未测试   [测速] [检查出口]
```

示例读数仅为设计示意，实际界面只展示真实结果。

- 点击节点即切换组内选择；成功后读取内核当前选择再更新选中标记。
- 展示当前选择、节点数量、协议、节点服务器地址与延迟；出口 IP 由独立检查得到，与节点服务器地址明确区分。
- 选择前置后，落地节点测试与真实请求使用该前置。更换前置会使依赖它的旧测速结果标记为过期。
- 组卡片默认折叠，展开才加载成员；成员搜索、分页或虚拟化，避免重复挂载数百节点。
- 桌面与移动端使用相同数据契约；窄屏按钮换行，当前选中项清晰可见。

## 实际使用与持久化

- 支持完整 YAML 中显式成员代理组，包括未作为 dialer 依赖出现的最终出口组。
- 将可用组作为稳定的代理池引用目标，账号和全局服务可以选择“落地-US-ISP”组。随后切换落地 IP，后续新连接跟随新选择，无需逐账号修改。
- 原有固定节点引用继续固定该节点，保留现有账号配置。
- 组选择按订阅 ID 和原始组名保存。内核重启和订阅刷新后恢复仍有效的成员；成员被移除时明确提示并展示内核实际选择，不能显示已经不存在的旧选择。
- 配置生成、切组与重启串行协调，防止持久化状态覆盖、切换与重建竞态；错误时不能展示虚假的“已保存”。
- 自动选择类组显示其实际类型和结果，只有内核允许手动选择的组提供切换操作。
- 不导入原订阅的全局路由规则、TUN 或监听端口。依赖缺失、循环或尚不支持的动态 provider 组给出明确原因。

## 测速与性能

- 延迟测试显示毫秒，支持单节点和组内批量测试；使用内核按节点测试能力，避免反复切换业务组影响真实请求。
- 下载测速显示 KB/s 或 MB/s，仅手动触发，默认单并发，每节点最多 5 秒或 5 MiB，支持取消；采用流式计数，不把下载体保留在内存。
- 测试地址可配置。测速结果附时间、测试类型和所用前置；出口 IP 单独检查，不能把总耗时冒充网络延迟或下载速度。
- 测速通过受限的本地测试出口执行，保持业务组选择不变；同一测试出口操作串行，取消和异常都释放锁与连接。
- 后端限制并发、超时和任务队列；页面隐藏时停止状态轮询，不自动启动批量测速。
- 原始密码、订阅鉴权 URL、控制器密钥不进入页面响应或日志。

## 验收

1. 合成订阅包含前置组、落地组及同名的第二份订阅，正确分组且不会串线。
2. 用两个可观测本地前置代理验证：切换前置后，落地流量实际经过所选前置；切换落地后，账号通过组引用访问新落地。
3. 内核重启、订阅刷新后恢复选择；成员删除、组移除、禁用订阅时状态明确。
4. 延迟、限量下载、出口检查与取消均有真实请求验收；测试不改动业务组选择。
5. 约 300 节点的折叠、展开、搜索与测速状态更新保持响应；页面隐藏后不继续轮询。
6. Rust 回归、前端类型检查、桌面与移动端构建、浏览器交互验证通过后更新本地 3065 服务。

实现顺序：先完成分组展示、切换与持久化，再接通账号组引用，最后完成测速、性能验证与本地服务更新。GitHub 推送和发版沿用仓库要求，单独确认。
