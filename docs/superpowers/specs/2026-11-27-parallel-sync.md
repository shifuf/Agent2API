# 两批上游选择性同步：实施边界

目标是让两批功能同时进入开发，而不是先合并上游、再找丢失的定制功能。面向已有 Docker 服务、桌面和手机管理端。本文是设计，不是支持情况或发布说明。

## 来源与取舍

| 用途 | 固定来源 | 处理 |
| --- | --- | --- |
| 定制基线 | `shifuf/Agent2API` 的 `728fdd041822e122576d02e580341b96eb61f169` | 在独立工作区实施，保留 3.5.1 版本与现有定制行为。 |
| 选取功能 | `aimod-cc/Agent2API` 的 `v3.6.0-beta.1` (`07a48a5f`)，审查截止 `74a4b330` | 根据实际文件追溯到原作者。包括 `091ac96c`（Lucas）的第一批核心、`e4b70ca5`（aimod）的任务商店下载修复、`74a4b330`（risore）的客户端标识归一化。 |
| 此后变化 | `0bb8d3f3` | 已见但不自动扩大范围；其 `sanitize_config` 变更不等于 `privacy_config` 修复。 |
| 现有 `sync-360` 草稿 | 同一定制基线，混有两批未提交改动 | 只作参考；不能覆盖、重置、假定已编译，不能取整份共享模块或暂存区。 |

**方案比较**：整包导入会带入移动端替换、代理订阅下线和网站更新器；沿用混合草稿则难以辨别谁已接上生产入口。采用**从干净基线并行实现可独立验收的功能**，集中接共享入口，以行为测试决定是否接纳，而非按文件数计进度。

## 交付边界

| 工作线 | 用户得到什么 | 验收边界 |
| --- | --- | --- |
| 一：余额 | New API 钱包及订阅额度、溢出与扣费偏好，两端一致 | 保留原有渠道鉴权与账号代理；附加接口失败仍可展示可信钱包，未知值不是 0。 |
| 一：隐私 | 可配置规则；出站替换 Key、邮箱、手机号、身份证和自定义词；流式/聚合返回还原 | 同一请求的多次尝试共享映射，不跨请求还原。普通日志、原始请求文件、debug、临时文件、备份和错误均不得泄漏请求中命中的原文；显式配置的保密词是加密的配置数据，不是请求样本。 |
| 一：通知 | Webhook、Telegram、Bark，管理员可配置、测试；实际登录、签到及授权任务事件可触发 | 禁用不发送；通道失败不能改变登录等业务结果。配置读取隐藏凭证；第三方错误不回显 URL、头或响应正文中的秘密。 |
| 一：定时任务 | 独立任务页与插件分类、单文件及商店包、动态表单与编辑器、多个实例、时区 Cron、单实例互斥、试跑、停跑与历史 | QuickJS，不是 Bun；显式授权主机、代理和通知；未授予的文件/进程/网络不可用。跨版本恢复可解密；运行记录不得保存 Cookie/密钥。商店校验下载包而非图标。 |
| 二：工具 | 生图/编辑 MCP、文本模型视觉替代、搜索多 Key 与额度状态 | 图像与视觉均通过授权的路由组；结果按调用者隔离；搜索的 Key 失败隔离，不把凭证返回管理快照。 |
| 二：转发 | 条件提示词、专门的标题路由、Responses 思考折叠 | 以原始公开模型匹配；正常对话不改路由。客户端标识忽略匹配大小写，模型公开拼写不能变；首内容前保活、两次失败冻结及不可重放约束不变。 |
| 二：计价 | 官方/自定义价格、分时费率、USD/CNY、请求费用和报表 | 与原有渠道倍率、原始 credit 和路由排序分开；费用是估算而非扣款。未知与真实零值不同，子请求不得重复计费。 |
| 二：运维 | Turnstile、Google/GitHub 登录与绑定、品牌名与 Logo、维护计划和历史 | 保留原密码登录、ALTCHA、限流与会话；绑定身份不授予额外权限。维护可刷新凭证/目录与提示插件更新，不自动安装或切换软件更新源。 |
| 二：扩展 | Claude、ChatGPT、Codex 订阅适配；Magpie/OpenCode 社区脚本插件 | 独立于 WASM/Native/QuickJS。仅显式授权的身份和适用的官方使用方式；本机 CLI、个人登录与可部署的多租户服务不视为等价。Codex 图片冷却与对话分离。Bun 不是沙箱；未隔离宿主或未经管理员信任不执行社区代码。 |

桌面从 `ui-islands` 接入现有导航，手机从 `mobile/src/pages` 接入现有页面；不复制上游 `views` 替换本地应用。适配包含两端可操作入口、持久化和失败反馈，而不是只导入 React 组件。未具备条件的宿主能力显示前置条件，不展示成功或虚报支持。新管理写入、配置测试、导入与凭证明文接口拒绝网关 Key。提供商矩阵仅按实际证据更新六种语言。

### 三个实现决策（待确认）

- **订阅与社区代码的交付门槛**：三种订阅各交付在其允许场景下的适配器和可执行契约测试；个人本机授权不能转成共享站点的凭据。没有适用授权或真实验收条件时，该提供商标为「外部验收待完成」，不是模拟成功就打勾。Bun 要在至少一个受隔离的 Linux 服务端环境实际运行本地固定插件，并验证无权访问数据目录、其他插件秘密和未授权网络；不能只交一个永不启用的开关。宿主不满足条件时禁止运行。Docker 不挂宿主控制 socket，不要求特权模式；上述条件无法满足时，该能力仍是未交付。
- **估价身份与时间**：优先按实际提供商、实际发送的模型 ID 查价，该模型的显式自定义价优于它的目录价；都无价才按原公开模型回退，仍无价记未知。用原请求时间选择分时段，结算时保存估算、来源和使用的汇率。刷新汇率或改目录不静默改历史；只有管理员显式重算才更新选中期间，并标识使用的新价格依据，旧 `credit` 不动。
- **辅助路由失败**：标题未命中或功能关闭时原路转发；明确命中但目标无权时用本地权限错误结束，失效/不可用时返回明确的路由错误，不悄悄按另一模型的价格执行。视觉替代失败不能把原始图片交给纯文本目标，也不使用未经授权的其他视觉组；只在调用者已授权且符合原重试契约的候选间选路，已发内容后不重放。

## 并行与合流

余额/搜索、隐私/转发、通知/任务、工具/计价、面板/维护、订阅/脚本宿主可以并行勘察与写独立模块。对 `api/{chat,protocol,pipeline}.rs`、`http.rs`、配置加载、数据库迁移/备份、导航与生成产物设唯一集成人；共享入口不做两份实现。先对齐契约再挂接：通知投递→任务 `notify`，路由组鉴权→标题/生图/视觉，隐私策略→落盘与流翻译，真实尝试记录→报表。`rquickjs` 和 Bun 分别验收，不把其中一个当另一个的依赖。

不采用上游统一错误/容量排队框架、整包移动端、本机直连采集、代理订阅下线、软件自动更新。对 Bun 和订阅不扫描个人凭据、不代操作真实账号、不将未经验证的服务声明为生产可用。需要外部授权的实时验收分开记录，不以 mock 冒充。新增运行时必须评估 Linux amd64/arm64；不改现有 GHCR 发布流程。

## 判定完成

用临时 SQLite、合成凭证、模拟上游做新旧行为对照、跨请求隔离、备份换机恢复、三协议实流和两端浏览器操作；再跑路由、倍率、密钥、代理、粘滞和云同步回归。基线结果不能当候选结果。按功能在 `docs/upstream-sync.md` 登记来源/作者、兼容方式、测试结果和未实测限制。用户随后要求验收后同步 GitHub 和服务器；按仓库红线，先审实际发布清单、版本及目标，明确确认前不创建发布提交、不推分支/tag、不操作生产。
