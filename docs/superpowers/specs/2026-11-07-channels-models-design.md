# 渠道、手动模型目录、代理订阅与 Docker

用户已选择「整个网关统一，按推荐直接实施」，跳过设计问答。

## 目标与方案

保留 Agent2API 的 Rust 服务端、React 岛和既有账号路由，参照本地 F:/axonhub 的渠道/Key 分组/模型关联交互实现。使用 F:/dns-panel 的推送触发 GHCR 构建模式。相较另建 Go 服务或只修改 API 模板，扩展当前系统能覆盖整个网关并复用凭证加密、代理、轮换和权限检查。

1. API 模板创建渠道：名称、协议、API 地址、多个命名 Key 分组；每组支持多 Key、启停、独立选取/手填上游模型。未保存的凭证可用于拉取模型候选，候选不得自动成为对外模型。渠道仍使用 custom provider 身份，凭证仍进入加密账号存储。真实选路必须按所请求的上游模型筛选 Key 分组。
2. 模型管理：对外模型由用户主动添加，配置对外 ID、一个或多个渠道/提供商和上游模型的关联；可编辑、停用、删除。上游目录只是选择来源，不能自动全量发布。列表广告、网关调用、模型选择器和网关 Key 的模型范围保持一致。使用独立 managedModels 目录存储对外 ID 与直接上游绑定，允许公开 ID 与上游 ID 相同并覆盖生图模型。现有 routing groups 继续作为用户显式创建的复杂路由入口。旧配置可读取，不删除账号、密钥和已有映射。
3. 网关 Key：可选择允许的渠道与手动发布的模型，限制必须在实际请求路由时生效，列表与执行一致；空选择的“不限制”语义要清楚，删除渠道不能导致权限静默扩大。
4. 代理订阅：从 v3.3.0-beta.5 恢复订阅增删改、URL/文件导入、刷新、节点池、内核下载/导入/运行/停止、账号和服务代理引用；兼容当前 3.4.2 的手动代理和 Clash 引用、备份与移动端；移除已下线提示。只恢复相关功能，不能回退版本或覆盖之后的无关修复。
5. Docker：自己的仓库 push main/beta 后通过 GitHub Actions 构建 GHCR 包，main=latest，beta=beta，并附提交标签；支持手动构建。构建包括最新前端，保留数据卷和健康检查，默认防止容器自更新覆盖私人维护功能。同步六份安装文档。此任务只准备本地工作流，不执行远程推送/发布、不修改版本号。

## 验证

重点覆盖不同分组模型隔离、别名到上游解析、Key 交集限制、空目录拒绝未添加模型、代理订阅解析与重启生命周期。执行 Rust server 检查/测试、React 类型检查与构建、移动端构建和工作流验证。环境不能完成的检查必须据实列出。
