# 官方 WASM 工具转发兼容

本批基于 `132e7d099a204b60513a807b9054372558e5f2c9`，继续处理用户已授权的官方插件兼容、GitHub beta 与 `175.178.69.4:3065` 部署。产品版本保持 `3.5.1`。上游审查固定为 `33f5e797836ac91d958022e9f4ca53c30d0432ec`。

## 已确认的两类问题

1. 官方 Raccoon WASM 0.1.1 的 GLM Flash、DeepSeek 目录声明 `supportsToolCall=false`，但同一启用账号、相同官方接口的真实原生工具调用和结果回传均成功。定制路由据此排除了可用成员。修正只适用于本次实际验证的 `sn-glm-5-3-flash`、`sn-deepseek-v4-1-flash-1017` 和加载时重新验签的官方 0.1.1 WASM；不扩大到其它模型、未签名包或其它版本。保留原始缓存声明，输出注明 gateway 来源；用户能力覆盖最后生效。
2. 官方 ChatGLM WASM 0.1.0 明确声明 `tagged_json_v1`、190000 字符预算，宿主缺少固定上游的 `web_tools` 流程。引入上游的声明校验、完整工具历史转换、离线 JSON Schema、关联随机值和完整终态确认。原生工具继续原样转发。

## 执行边界

- 保留真实账号、Key 来源、模型和账号权限、代理、执行代次、租约、ReplayGuard、取消及 usage。工具由客户端执行。
- 模拟只消费当前握手声明的有效 profile；旧缓存、降级插件和图片不得自行授予能力。默认开关与上游一致，可由真实管理接口保存；设置变化立即使目录缓存失效。
- 无真实终态、截断、非法关联值、未知工具、参数不合法、复制历史调用示例时不输出可执行工具，不自动重发已提交的请求。
- 只推 `origin/beta`，不推 main、不打 tag、不建 Release；当前已有发布和直接部署授权继续有效。
- 部署前重新备份当前现场；验收双架构镜像的 revision 和 digest，再替换目标容器，保留现有数据和旧容器回退。

## 验收

原始签名 Raccoon 和 ChatGLM guest 必须经过正常临时 SQLite、真实 Key 和路由组路径，验证流式、聚合、工具调用及工具结果回传。另验证无效响应、取消、缓存降级、用户覆盖和权限。运行正常 Cargo 库测试、工作区检查、服务端构建及受影响的 HTTP 回归；发布前进行独立源码评审。生产再次验证现有允许的公开模型和钉住账号，不将安装契约通过写成所有外部账号均实时调用成功。
