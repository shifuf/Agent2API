# Isolated community hook probe implementation plan

**Goal:** let a panel administrator test the current retained archive by name and SHA-256, without installing it or giving it network, credentials or gateway filesystem access.

**Approved design:** use a fresh single-vCPU Linux x86-64 TCG guest, not Bun as a security boundary. Prep a root-owned, non-writable kit out of band. Feed the reviewed standalone ESM entry only as a private, bounded initramfs overlay. The guest result is a diagnostic only; never expose guest stdout, add permissions or change the archive. Other platforms, root gateways and missing prerequisites must decline.

- [x] Run a real HTTP fixture against the old binary, proving the admin-only entry does not exist (404).
- [x] Add archive compare-and-read, offline validation, immutable guest configuration and a bounded, cancelable QEMU process.
- [x] Prepare the kit using the pinned Bun distribution and trusted local Linux files, without fetching dependencies or running package scripts.
- [x] Exercise missing prerequisites, stale hash, success, isolated guest, failure, single-slot exclusion and cancellation through the actual gateway endpoint.
- [x] Document deployment in the six install guides and distinguish `server()` diagnostics from plugin installation, subscription auth and model routing.

## Verification

- Linux amd64: `cargo build --locked -p agent2api-server --bin agent2api-server` and the same command with `--features task-plugins` produced identical debug executables (SHA-256 `6c165e29d90ad59c08cb9a51aba9633dc97f05b36b64ea24cf79b6e795f37d4e`). The default already includes `task-plugins`; no `--no-default-features` flag was used.
- `scripts/test-sync360-community-linux-guest.py` boots a disposable offline Linux host and runs the actual unprivileged gateway there. The HTTP fixture creates and retains a synthetic package, then the gateway launches its own separate TCG guest. Windows and Linux without the trusted kit refuse the probe. WSL1's incomplete capabilities/seccomp support was not bypassed to run community code.
- The default 80-second wall / 65-second CPU budget is too short for a successful hook under double software emulation on this test machine. Using a 300-second operator budget, a retained hook returned HTTP 200 with the fixed diagnostic fields. For both budgets, cancellation reaped the process; live `/proc` assertions checked CPU/address-space/core limits, no privileges, seccomp, one vCPU and no NIC. Invalid values `unlimited` and `301` each disabled the feature and returned HTTP 503; a separate Linux unit test covers both boundaries and malformed/non-Unicode values.
- The same-name v1→v2 update and rollback invalidated the displaced digest each time. Extra timeout/permission/install request fields were rejected. A throwing hook that printed the success string still returned a sanitized 422. A successful hook left registry, panel, provider/account feature, archive and policy state unchanged.
- The first 300-second sleeping fixture returned 422, **not** 504; no signal trace was taken in that run. The replacement 30-second test separated the two clocks on the same ELF: a stopped QEMU used 0.7 seconds of CPU and returned 504 after 31.7 seconds (gateway signaled `SIGKILL`); a running QEMU hit its 15-second CPU limit, returned 422 after 17.4 seconds and was killed by the kernel (`SI_KERNEL`). Both processes were reaped. Only the gateway's wall watchdog reports 504; 422 is not an assertion that a particular signal or guest failure occurred.
- After the separate v26/v27 SQL migration fix, the default Linux amd64 candidate (SHA-256 `2ddcb5c7d587a38070110ffb17d068feb4332874c5d6fb96ab8d7c44d53269ae`) passed the real gateway HTTP suite again, using a bounded 300-second budget. Both the successful hook and the throwing hook left the active plugin packs, admin panels, account features, provider docs, plugin settings and retained archives unchanged. The bad hook returned 422 without exposing its printed marker. Authorization, digest/rollback, process limits, exclusion and disconnect reaping also passed. The independent 30-second wall/CPU signal measurements above used the earlier ELF and were not repeated on this candidate.
