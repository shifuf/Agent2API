# 路由 524 与插件失败顺延修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 尚未交付内容时，普通上游 524/503 继续尝试可用账号或渠道，不因插件通用 Fatal 分类或渠道数量预算过早结束。

**Architecture:** 保留现有首内容预读、账号权限、取消和重放保护。暂时失败由路由循环处理，渠道连续两次失败仍冻结；计算路由预算时覆盖账号候选。已经交付的流不拼接第二份回答。

**Tech Stack:** Rust、Wasmtime、Node.js 隔离 HTTP 验收。

**Spec:** 用户要求在当前请求中顺延候选，全部可用候选失败后再返回错误；此前明确要求渠道连续两次失败冻结。

## Global Constraints

- 保持上游版本 3.5.1；发布前另行确认新日志，只允许 beta 和 175 服务器。
- 不使用生产账号生成测试请求，不保存生产请求正文。
- 不取消插件 stop、retry_forbidden、账号权限或客户端取消保护。
- Wasm 计算/栈故障需实际复现后才能调整额度，不直接扩大或取消沙箱限制。

## Review Focus

- HTTP 524 空响应仍按状态进入顺延，不依赖正文文本。
- 插件 Fatal 是普通失败分类，显式 stop 才禁止重试。
- 同一渠道多账号限额不能因渠道数预算漏掉末尾可用候选。
- 权限拒绝、无有效成员、客户端取消不能继续发请求。
- 已发送文本、推理或工具调用后错误不能启动第二份回答。
